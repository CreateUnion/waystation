# waystation 编码规范

> 本文件是项目特化编码规范的落地实例（通用风格规则以 AI 工作区「AI 开发规则」（`CLAUDE.md`）「编码风格规则」CS-01..CS-10 为权威）。
> 本文件只写：项目特化决策、工具化落点、以及 CLAUDE.md 授权项目维护的补充口径。写代码前先读本文件。

## 样板文件

新代码「照它们的风格写」；样板过时先更新样板，禁止「样板归样板，新代码另起风格」：

- `src/net/dispatch.js`——典型业务模块：完整错误处理、可注入依赖、注释写「为什么」；
- `src/config.js`——默认值与校验的单一权威源写法（字段规则表 + 显式回落）。

## 命名

| 项 | 规则 | 好例子 | 坏例子 |
|---|---|---|---|
| 变量 / 函数 | camelCase，动词开头、说清做什么 | `remember`, `markAcked` | `data`, `tmp`, `handle2` |
| 常量 | UPPER_SNAKE_CASE | `MAX_FRAME_BYTES` | `maxFrame` |
| 文件名 | kebab-case 或单关键词（与导出主符号对应） | `known-hosts.js`, `protocol.js` | `util.js`, `new1.js` |

- 禁止泛名：`data` / `tmp` / `result` / `info` / `handle` / `process`——除非该词就是业务本名；**存量泛名不追溯**（随触随改），新代码一律拦截；
- 模块私有状态结构体惯例：工厂函数内 `state` 闭包（模块级可变全局禁新增，存量登记见「CS-04 适用口径」）。

## 函数结构

- 单函数 ≤ 40 行（含签名与注释行口径见下）、嵌套 ≤ 3 层、圈复杂度 ≤ 10——ESLint 强制（`eslint.config.js`）；
- 一个函数只做一件事；描述需要「和」字时拆分；直白且仅少数调用点的逻辑直接内联（CS-05 判据）；
- **行数口径（项目补充裁定）**：`max-lines-per-function` 以 `skipComments + skipBlankLines` 配置（`eslint.config.js`），即**含签名行、不计注释与空行**——40 行约合 38 条语句；拆分时提取**具名**函数。

## 注释

- 写「为什么」不写「是什么」；中文表达习惯，不做英文直译（CS-08/CS-09）；
- **不带开发过程编号**（批次/问题/任务/里程碑），溯源归 commit message 与计划文档；技术文档出处（设计章节、TRM 章节、协议文档）属豁免；
- 机检：`test/comment-discipline.test.js` 扫描 `src/` 与 `bin/`；
- **pattern 已知边界（登记，触发条件=实际误报出现时收紧）**：词形 `SSD M2`、`G1 GC` 等英文语境可能误报；`M10` 以上编号的 pattern 可能漏报；扫描为整行匹配（含字符串字面量）。

## 错误处理

- 运行期**绝不因内部错误 / 写盘失败 / 日志异常退出进程**（设计 §6 硬性要求）；唯一例外是启动自检的「拒绝服务」（有意退出，退出码 1）；
- 入站数据一律显式校验、**拒绝并计数留痕**（`log.warn` + `stats()`）；「忽略」必须带计数器与注释理由；
- 只读接口的失败不得静默返回空——「没有数据」与「读不到」必须可区分（工具面以 `isError` + 明确文案承载）；
- 可注入钩子（`admit` / `consume` / `deliverToSession` / `describeCollab`）的异常一律隔离并归入最保守语义，绝不让异常穿到调用链。

## 数据结构

- 模块对外形态：`createXxx({ 依赖 })` 工厂 → 返回对象含方法与小写 `state` 闭包；依赖全部经参数注入（便于替换与单测）；
- 常量落点（单一权威源）：数值默认值 → `config.buildDefaults`；协议/跨端共享常量 → `src/net/protocol.js`；站点端口锚点 → `src/site.js`（`ANCHOR_PORT`；槽位函数与 `slotDefaultPort` 退役为历史/测试面，单核运行时不再使用）；**单核端口语义**（`config.port` 显式值／主根未显式取锚点 7321／显式根未显式配 port 拒绝启动——`src/core/main.js`）与 **IPC 端点命名**（Windows `\\.\pipe\waystation-<rootDigest 8hex>`／POSIX `<根>/run/core.sock`——`src/core/ipc.js`；命名规则纳入「发布前登记」挂账，见下「核心/桥分层边」条）；模块私有运行参数 → 模块顶部定义并注释理由；
- **端口范围判定唯一权威 = `protocol.isPort`**（1–65535 整数）：本地配置、入站帧、工具参数与本地存储读取一律经它判定，不得就地重写判据；
- 持久化形态：JSONL 追加 + 整体替换（`src/storage.js`）；旧数据兼容策略必须写明「缺省解释」，不引入文件级迁移（除非写明版本字段与迁移）；
- 消息/记录对象字段名沿用既有拼写（`msgId` / `collabId` / `lastSeenAt`），不得引入同义新名；
- **幂等去重域 = 协作域**：msgId 去重按协作（收件流水按 collabId 隔离）进行，不设跨协作全局索引——msgId 由构造侧 UUID 保证唯一，跨协作同 msgId 只可能来自伪造/客户端缺陷；治理转达（沿用原 msgId）在协作内完成。

### 分层边界

| 惯例 | 好例（既有代码实样） | 坏例 |
|---|---|---|
| 进程级副作用（自检、装配、监听、退出）只在组合根 `src/index.js`；其余模块导入无副作用，只导出工厂与纯函数 | `bin/waystation.js` 极薄——仅 `import '../src/index.js'`；`src/net/*` 全部 `createXxx` 工厂，由组合根装配 | 模块顶层自启监听 / `process.exit` |
| MCP SDK 的 import 面收敛在 `src/server.js` 与 `src/index.js`：`net/` 与 `tools/` 不 import SDK，逻辑层可脱离 MCP 宿主直接单测 | `src/net/dispatch.js` 无 SDK import | 网络或工具模块 `import '@modelcontextprotocol/sdk/…'` |
| 工具经注入的 `context` 取能力，`tools/` 与 `net/` 互不 import | `tools/delivery-status.js`：`context.net.deliveryStatus(...)` | 工具文件 import `../net/dispatch.js` 自建能力 |
| 依赖方向下行（`index` → `server` / `tools` / `net` / `site` → `storage` / `paths` / `log`）；逆向边登记且无环 | `paths.js` / `config.js` / `site.js` → `net/protocol.js`（校验函数同源复用；`protocol.js` 只依赖 `node:crypto`、是叶子节点，不成环） | `net/` import `tools/`，或新增成环的逆向边不登记 |

**为什么**：SDK 与传输细节收敛在组合根，逻辑层与工具面才能脱离 MCP 宿主、直接实例化工厂做单测；逆向边集中登记且无环，防 import 成环与启动顺序漂移。

- **同级横向边（登记）**：`net/known-hosts.js` → `site.js`（复用 `ANCHOR_PORT` 单一权威）——无环、登记在案的横向引用。
- **程序级模块边（登记，人类观察窗）**：`src/viewer/*`（本地只读观测工具，非驿站运行部件、零协议面）→ `src/paths.js`、`src/util/digest.js`、`src/collab/{posts,members,store,model,counter,mute}.js`、`src/net/protocol.js`——只引纯读/判据符号（白名单与禁写纪律见观察窗设计 §5.2：`store.js` 只许 `loadMember`、`mute.js` 只许 `isMuteShape`（`createMuteStore` 写面不 import），禁 `loadLines`/`loadLedger`/`loadConfig`/`saveConfig` 等一切带写能力符号）；`src/viewer/server.js` 与 `src/viewer/launch.js` 改引 `src/util/digest.js` 并保留再导出（同层、无环；中立模块边见下条）；`scripts/ws-viewer.js` 为观察窗组合根，入口副作用仅在其内。
- **核心/桥分层边（登记，单核）**：`src/core/*`（核心：LAN 栈、锁与生命周期、注入路由、IPC 服务端、工具 handler 的执行者与数据面单写者）与 `src/bridge/*`（桥：会话内 MCP 门面＋本会话注入口写入端）——**桥只引**：`paths.js`、`server.js`、`tools/specs.js`、`adapters/claude-code.js`（`bridge/session-writer.js:1`，注入口写面复用）、`core/lifecycle.js` 的**判据原语子集**（`bridge/ipc-client.js:6`——判死/对证类原语如 `pidIsAlive`、判死阈值 `judgeMs`〔`lifecycleParams(env)`，`bridge/ipc-client.js:82`/`:111`〕；**禁触仲裁/宽限等核心内部面**——`lifecycleParams` 返回包中的 `graceMs`/`waitingMaxMs` 等字段桥未消费）、`core/stop-guard.js`（`bridge/ipc-client.js:7`——硬杀防护链；**共享件**：核心侧直接消费方＝`core-cli`〔`src/core-cli.js:402` 按需动态 import——模块边登记〕与桥〔`ipc-client.js:7`〕；`core/changeover.js` **经注入消费其结论**，不直接 import）、`bridge/*` 与 MCP SDK（SDK 面沿组合根收敛口径，`src/bridge/main.js` 为桥的组合根）；**桥禁 import 服务层与数据层**（`collab/*`、`net/*`、`tools/*` handler、`storage.js`、`config.js`、`log.js`——核心不在时桥不读不写数据根；`net/*` 唯一例外＝协议常量叶 `net/protocol.js` 经 `ipc.js` 间接，不直引）；**`adapters` 两向边（登记）**：桥 → `adapters/claude-code.js`（注入口写面复用，上列）与核心 → `adapters/claude-code.js`（`core/routing.js:7` 的 `renderSessionMessage`——纯渲染复用，不读凭据）；**核心禁触会话凭据**（不接收、不持有注入口 socket 路径与 token——凭据只存于桥进程 `src/bridge/session-writer.js`；核心的 `push` 帧只承载一段已渲染文本）；依赖方向＝桥 → `src/core/ipc.js`（两端共用的帧/端点契约叶子，只依赖 `paths.js`/`util/digest.js`/`net/protocol.js`）← 核心；IPC 端点命名规则与端口分配语义同属「发布前登记」挂账（主设计 §18 口径；IPC 协议对外零承诺，不进永久契约清单）。
- **桥合成 `ws_status` 差错载荷（登记例外）**：核心不可达时由桥合成 `isError` 载荷（`core:{available:false, reason}`，其余字段省略）——「桥是纯转发件」原则的**唯一登记例外**（设计 §8 写死；不填占位、不伪造）。
- **`src/tools/specs.js`（登记）**：23 工具规格**纯数据**模块（零 import、无运行时依赖）——核心（注册 handler）与桥（应答 `tools/list`）共同导入；桥只读消费，不引任何 handler；规格字面量的一致性由 `test/tool-specs-freeze.test.js` 反查守护。
- **`src/util/digest.js`（中立模块，登记）**：`rootDigest`（8 hex）的唯一定义——观察窗（health/端口自发现/`--stop` 根匹配）与核心（IPC 端点命名，`src/core/ipc.js`）共同导入；消费方一律经本模块引用，不再各自实现。
- **`ipcV` 纪律（登记）**：IPC 帧协议版本 `IPC_VERSION`（`src/core/ipc.js`）只在帧协议真变时**人工 +1，不随 app 版本递增**（换代兼容判定的独立维度）。

### IPC 安全登记（单核，如实披露）

- **信任边界**：本机同用户进程视为可信；端点权限与 token 是纵深防御，**不是**对抗同用户恶意进程的保证。POSIX：`run/` 显式 0700 创建、`core.sock` 0600——token 保密性由 `run/` 自身 mode 承重，无法保证 0700 时 token 不构成秘密（告警如实登记）；Windows：命名管道默认安全描述符（同用户可连，实现期实测口径）。
- **桥侧冒充（放大面如实登记）**：IPC 端点对同用户任意进程可连、token 同用户可读——伪造「桥」连上并注册后可发 `call` 帧**驱动全部 23 个 handler**（含同意门/裁定/终结/抢接）并可经绑定接管读取全部注入内容；相对既有形态（同用户进程要达成同等效果须自实现 LAN 协议与入网寻址）**门槛显著降低**——如实登记，不做「今天亦然」类比淡化。
- **B1 回落 A（裁定链与探针）**：设计裁定 B1＝进程身份校验（连接方须为会话进程子进程）；实现期首验**不通过**——Node 核心面拿不到对端进程凭据（Windows 命名管道客户端 pid 不可得、POSIX `SO_PEERCRED` 无 JS 绑定；强做须引入原生扩展＝新增依赖停点）→ 按设计预设**回落 A（接受＋如实登记）**，未实现进程身份校验；结论固化于 `src/core/ipc.js` 模块头；**探针用例留守**：`test/ipc.test.js` 的「B1 首验固化（Windows）」用例以枚举断言看守 Node 面（POSIX 同结论在证；Windows 之外平台该用例按 skip 标注）——若新增对端凭据 API 会**转红**，提示重估本结论。

### 空值惯例

- `undefined` = 语言层「缺失」：Map 未命中、可选参数未提供——用 `=== undefined` / `!== undefined` 判定（`tools/registry.js` 未知工具、`tools/delivery-status.js` 可选过滤参数）；
- `null` = 业务「无值」：进入落盘记录与工具输出的字段一律显式归一到 null（`dispatch.js` 状态行 `ackedAt: entry.ackedAt ?? null`；`config.js` 可选参数 `options.slot ?? null` 先归一为 null 再分支）。

| 坏例 | 好例（既有代码实样） |
|---|---|
| 记录字段留 `undefined` 直接进 JSONL / 工具输出——序列化丢弃 undefined 字段，回读形状与写入时不一致 | `ackedAt: entry.ackedAt ?? null` 显式归一后再输出 |

**为什么**：JSON 序列化丢弃 `undefined` 字段——null 可落盘、可回读、输出形状稳定；「语言层缺失」沿用 JS 原生 undefined 语义，避免与「业务无值」混为一谈。

### 错误惯例

- 校验接口以结果对象表达：通过 `{ ok: true, ... }`、失败 `{ ok: false, reason }`（`protocol.js` `refuse`）；段间委派用 null 表「本段无异议」。调用方按 `ok` 判定并**拒绝计数留痕**（`transport.js` `protocolViolations++` + `log.warn`）——不抛异常穿层；
- 工具 handler 契约 `{ content: [...], isError? }`；handler 抛错由 registry 兜底为 `isError`（异常不穿到 SDK）——「没有数据」与「读不到」因此可区分（策略见「错误处理」）；
- `throw` 只用于编程 / 装配错误（工具名重复、非法槽位 `TypeError`）——启动期即暴露（fatal 退出码 1）；运行期路径不 throw 穿到事件循环。

| 坏例 | 好例（既有代码实样） |
|---|---|
| 协议校验失败 `throw new Error('msgId 非法')`——穿到帧循环、无法按帧计数留痕 | `const checked = validateMessage(wire); if (!checked.ok) { …按 reason 拒绝并留痕… }` |

**为什么**：网络边界的错误是可预期的业务数据（对端帧来自任意实现、不可信），以数据形态返回才能逐条留痕且不中断管线；`throw` 留给「自己代码违反合同」。

### 命名后缀

| 后缀 | 含义 | 好例（既有实样） | 坏例 |
|---|---|---|---|
| `...At` | ISO 8601 字符串时间戳 | `lastSeenAt`（`new Date().toISOString()`）、`ackedAt` | `lastSeenTime`（形态不明的数值） |
| `...Ms` | 整数毫秒时长 | `probeTimeoutMs`、`dialTimeoutMs`、`retryIntervalMs` | `probeTimeout: 1`（秒还是毫秒？） |
| `...Id` | 标识（小写 d 结尾；构造经 `newMsgId()` 的 UUID） | `msgId`、`collabId`、`instanceId` | `msgID`、`messageKey` |
| `...Dir` | 目录路径 | `dataDir`、`logDir` | `data`、`logPath` |

- 判定函数前缀 `is`（`isPort` / `isIdentityName`）、工厂前缀 `create`（`createXxx`）、解析归一前缀 `resolve`（`resolveDataDir`）；
- **为什么**：单位与形态进名字，跨模块引用与配置字段（字段规则表逐字沿用同后缀）无需额外注释即可判定口径，杜绝秒 / 毫秒换算漂移与字段误读。

## 类型面说明（项目补充裁定）

- `checkJs` 覆盖 `src/` + `bin/`；`strict: true` 但 `noImplicitAny: false`、`useUnknownInCatchVariables: false`（存量基线，见 `tsconfig.json` 注释）；
- **测试文件暂不纳入 tsc**（测试无 JSDoc 注解、收益低噪声大；后续评估）；
- **`@types/node` 钉 `^22`、与运行时对齐，但类型面不替代运行期验证**：声明可能领先于本机运行的 Node（如 `registerHooks` 声明存在而运行时缺失）——凡依赖 API 存在性的判断，以实际运行验证为准（CI 与本地 gate 都是运行期证据）。

## CS-04 对 JS 模块的适用口径（项目补充裁定）

JS 模块不存在「同模块 ≥2 个全局变量」的编译期形态，口径落为：**可变模块级状态才需要聚合**——一个模块若持有可变运行态，聚合进工厂闭包的单个 `state` 对象；`const` 绑定（常量、纯函数、导入的依赖）不计入、无需聚合。

**存量登记基线（不追溯）**：`src/index.js`（组合根）现有两处模块级可变绑定——`instanceId` 与 `sessionEnded`。组合根是以进程生命周期为界的装配脚本，两处各承载一份进程级单例状态（实例标识 / 会话关闭去重）且不被其他模块引用，按 CS-10「存量不追溯」同款口径登记。

**禁止新增模块级可变全局**：新模块一律工厂 `state` 闭包；跨模块共享的运行态经构造参数注入。
