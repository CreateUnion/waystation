---
description: 申请加入一条协作或讨论（用法：/ws-join <协作/讨论名 | 标识> [目标驿站…]）
---
<!-- waystation-managed-command -->
用户要用 waystation 加入一条已有的协作或讨论。参数原文：$ARGUMENTS

流程：

1. 若本会话没有 waystation 工具（`mcp__waystation__*` 不存在），提示用户：本会话未加载驿站工具，请**新开**一个 Claude Code 会话再试，不要继续。
2. 先调 `ws_list_collabs` 看本机参与清单做判断：目标已在清单里（本机在席）→ 直接调 `ws_join`（给 `collabId`）——讨论＝本会话接线**立即生效**（无批准门）；协作＝已在席：本会话**已获准**而席位被他会话占用时无需重复申请（让持有席位的会话退出或关闭后即可接收）；**未获准**则本次调用即申请。
3. 目标不在清单里：
   - 用户给得出标识（`collabId`）→ `ws_join` 带 `collabId`。
   - 只给了名称 → 先 `ws_list_hosts` 找目标驿站（取 `hosts` 段的 `instanceId`，或地址与端口），再 `ws_join` 带 `name` ＋ `target`（`{ instanceId }` 或 `{ address, port }`）——先对该目标单播按名解析，**名称不广播**。
   - 名称对不上任何在线驿站、也对不上本机在册记录，而用户要找的是**讨论**且不知道在谁那儿 → 不带 `target` 调 `ws_join`，走敲门路径；如实提醒用户：敲门会把讨论名播给全网（局域网可见），且在场无人放行就不会成功。
   - 拿不准/多重含义 → 列候选让用户挑，不要猜。
4. 协作的申请不会立刻生效——如实告诉用户：**需要对方站长批准**（对方调 `ws_approve_join`）；批准后本会话才接线、开始收注入。讨论的敲门路径＝等任一在场成员放行（对方执行 `ws_invite` 邀请你）→ 你在同意门确认后加入。
5. 用户是站长、要处置别人的加入申请时：`ws_list_collabs` 的 `pendingJoins` 列出待批准（含申请人会话短码），用 `ws_approve_join`（`collabId` ＋ `sessionId` 短码 ＋ `approve`；拒绝可带 `reason`）处置。**批准是活人点头**：只有用户明确表示同意才批，不要替他决定。
6. 回执：如实转述返回状态（申请已发到站长 / 已进本机待批准面 / 讨论已接线 / 等待放行），不要只说「成功」；工具报错（无会话标识、端点未知、未获准等）原文转述，不要自行重试或换目标。
