启动后先确保 dispatch 在位：ws_status 查无 → ws_create_collab {name, mode: dispatch, autoClaim: true} 建队（autoClaim 立即自动收编一轮可绑定会话，并随核心节拍持续补收新会话、自动移除离线 slave），随后向用户汇报成员清单，每项带会话名称和会话 ID（ws_status 的 dispatch.slaves 可取）；已存在 → 直接复用；若创建被拒（已存在）说明现任 master 在位，隔一分钟重试一次。成员加入事件到达时，对新入编成员自动补发一条标准状态询问 task（在做什么/已完成什么/有无卡点待裁定）——收编通知本身已携带上报要求，成员未响应再补发这一次即可，不要重复催促。后续 ws_dispatch_scan 查看成员与各会话 claimable 状态（claimable=false 的不可收编，不要认领）；scan 结果偏少（如只见个别 ai-xx 会话）多半是核心重启后各桥还在重连，隔几秒重扫一次再看，不要当成最终名单；个别未入编目标可 ws_dispatch_claim 手动收编，交互式返回 pending 属正常，等对方确认，不要催促；3) ws_send_message {collabId, type: task, toSessionIds, taskId} 下发任务，收 progress/result，type 只用 task/progress/result/error；4) 结束用 ws_dispatch_release 释放单个或 ws_end_collab 整体结束。
纪律：dispatch 消息只走本机核心不占微信额度；给用户的回复合并为一条汇总，不要逐条转发 slave 消息；slave 的 result 已含结论时不要重复追问；dispatch 是纯内存的，核心或 cc-connect 重启后需重建（重建时带 autoClaim: true）。
拉起 worker（用户要求在指定目录开工时，用 Bash 执行，两步走）：① 用 Write 工具写全 ASCII 批处理到 C:\\Users\\xueco\\AppData\\Local\\Temp\\worker-<名>.cmd——内容四行：cd /d <目录>、set WAYSTATION_ROLE=slave、set WAYSTATION_MASTER=<本会话名>、claude --name worker-<名> -p "<初始指令>" --permission-mode dontAsk --allowed-tools "Read Grep Glob Bash Edit Write mcp__waystation__ws_send_message mcp__waystation__ws_status mcp__waystation__ws_leave_collab"；任务含中文时必须先把完整任务书落盘为文件（ASCII 路径），批处理里只写『读 <任务书路径> 并严格执行，完成后按任务书回传节回报』——批处理与任务书文件名一律全 ASCII（cmd 按 GBK 解析批处理，UTF-8 中文会乱码毁参数）。② Bash 后台执行 cmd //c "<批处理绝对路径>"（run_in_background，完成自动通知）。禁止用 cmd /c "start ..." 嵌套引号配方（Git Bash 下转义必坏）。无头入编即干活（用户已明确选择 dontAsk+白名单模式；白名单外工具一律会被拒，属预期）。
弹可见交互窗（用户在电脑前或要接管时，用计划任务中转开进用户桌面）：schtasks /create /f /tn ws-open /tr "cmd /k set WAYSTATION_ROLE=&& set WAYSTATION_MASTER=&& cd /d <目录> && claude" 加 schtasks /run /tn ws-open（新交互窗）；接管某个 worker：ws_dispatch_scan 拿它的 sessionId，/tr 换成 "set WAYSTATION_ROLE=&& set WAYSTATION_MASTER=&& cd /d <原目录> && claude --resume <sessionId>"——**必须先清掉 WAYSTATION_ROLE/MASTER 再起 claude**（cc-connect 服务环境带 master，不清会把被接管的会话以 master 身分复活，抢走 dispatch 主位），用户即可在窗口里直接续着打字。用完 schtasks /delete /f /tn ws-open 清理。
